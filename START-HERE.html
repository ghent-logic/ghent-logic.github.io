YOUR WEBSITE · FINISHING GUIDE

The design is done.
Now make it yours.

Six pages, working links, a coloured navigation bar, responsive layouts, and reusable content.

Open your website →

1. Look at the finished design

Unzip the entire download first. Open index.html in Chrome, Edge, Firefox, or Safari. Click through the navigation at the top. Resize the window to see the mobile layout. Click “Read abstract” on a seminar to expand it.

You do not need an installation, terminal, Jekyll, or a domain to view it.

Why this differs from the previous package: the previous version needed Jekyll to assemble it. This version uses ordinary HTML, CSS, and a little JavaScript. It works directly on your computer and on GitHub Pages. Keep this as a separate project; do not mix its files with the old Jekyll files.

2. Edit one content file

Open content.js in a plain-text editor, not Microsoft Word. On GitHub, open the file and click the pencil icon. Locally, use an editor such as VS Code, Notepad, or TextEdit in plain-text mode.

This is a JavaScript data file, but you do not need to write programs. Replace the text inside quotation marks:

name: "Ghent Mathematical Logic",
university: "Ghent University",
department: "Your actual department",
email: "your-real-email@ugent.be",
address: ["Building", "Street and number", "9000 Ghent, Belgium"],

Keep the commas, square brackets, and quotation marks. Use straight quotes ("), not typographic “smart quotes”. If your text contains a double quote, write \", or use curly quotation marks inside the text.

Leave unavailable URLs as "". The site will hide their links rather than send visitors to a fake destination. All of this file is public, so never add passwords, private meeting links, or unpublished personal details.

After saving, refresh the page. On GitHub Pages, wait for publishing to finish and then refresh.

3. Replace the sample entries

Further down content.js, you will find people, seminars, and activities. Each entry begins with { and ends with }. Copy a complete entry to add another; separate entries with commas.

Members and photographs
{ name: "Actual member name", initials: "AB",
  group: "Academic staff", role: "Professor",
  area: "Proof theory", bio: "A short, accurate biography.",
  photo: "assets/images/member-name.jpg",
  profile: "https://your-real-profile-address",
  email: "", sample: false },

Put a photograph in assets/images/ and enter that path. Leaving photo: "" gives an initials portrait. Use photographs and personal details only with the relevant permission. Empty profile or email fields do not create non-working links.

Seminar dates and abstracts

Dates use YYYY-MM-DD, for example "2027-03-12". Times use a 24-hour clock, for example "14:00", interpreted as Ghent local time. These are format examples, not scheduled talks.

The homepage automatically shows the first upcoming talk. Once a talk’s date has passed in Ghent, it moves to the archive. Set archived: true to archive a talk manually. Blank dates are displayed as “To be announced”.

Give each talk a unique id, for example "smith-proof-theory". Optional onlineUrl and slidesUrl fields become working links when filled.

Activities

Each entry names its kind: every distinct kind becomes a section of the Activities page, in the order the kinds first appear in the file, with a jump link at the top. Invent a new kind by typing one. when and where appear above the title, description takes a paragraph or a list of paragraphs, and url with linkLabel and contact become links beneath.

For each completed record, set sample: false. When the whole site is ready, set the top-level preview: false. This removes the preview banner and hides any records still marked as samples. It does not automatically validate your other text.

4. Review the words—not the layout

The homepage introduction and three research areas are written as draft copy. Review them for accuracy: I do not know your group’s full membership or remit. Change them in content.js. The example areas are proof theory, non-classical logic, and logic in computer science.

Short introductory paragraphs on the inner pages live directly in their HTML files. You can keep them or edit the text between the tags. Update any university-specific wording in the page descriptions in <head> if you change the institution.

5. Keep the colours—or change three values

Navy · #132d46Teal · #12665fGold · #f2c66d

The first line of assets/style.css contains:

--navy: #132d46;
--teal: #12665f;
--gold: #f2c66d;

--navy is the coloured navigation bar; --teal is used for accents; --gold marks the current section. The darker footer has its own --navy-deep value. You do not have to change any of these.

6. Publish on GitHub Pages

  1. Keep a backup of any existing website. Use a new repository for this version if you do not want to replace the old one.
  2. For an organization homepage, create the public repository ORGANIZATION.github.io, using the actual organization name in lowercase.
  3. Upload the contents of this website folder, not the ZIP itself and not an extra enclosing folder. index.html must be at the top level. Keep the assets folder intact.
  4. Include .nojekyll. If hidden files are not uploaded, choose Add file → Create new file on GitHub, name it .nojekyll, and commit it.
  5. Open Settings → Pages. Choose Deploy from a branch, branch main, folder / (root). Save.
  6. Wait for publishing, then use the Visit site link on that settings page.
  7. Only after that works, verify your domain and connect it using GitHub’s official instructions. Set the custom domain on GitHub before adding DNS records pointing to Pages. Enable HTTPS.

If using an existing repository, do not leave the previous index.md beside this index.html. The new website does not use the old _layouts, _config.yml, or Markdown pages. Preserve your existing CNAME domain file if there is one.

Launch checklist

  • Correct group and department names, contact email, and address.
  • Research descriptions reviewed; no claims that do not apply to your group.
  • Actual members, photographs, and profile links added.
  • Reading groups, courses, and other activities described, or samples removed.
  • Real seminar dates, locations, and abstracts added, or samples removed.
  • Every completed record has sample: false; the top-level preview is false.
  • Click each navigation link and test the narrow-screen menu.
  • Test every external link and email link.
  • Review university branding requirements; the ∴ mark is an original neutral symbol, not an official university logo.
  • Two group owners, two-factor authentication, automatic domain renewal, and HTTPS enabled.

No contact form is included: email links open the visitor’s mail application. This avoids pretending that messages are sent by a static site. No analytics, third-party fonts, cookies, or tracking scripts are added by this package. The hosting provider still handles visitor requests.

All files and artwork in this package are editable. No paid theme or subscription is required by the website code. Hosting, domain registration, and any future services remain separate. This site uses JavaScript for shared navigation and data-driven content; keep it enabled when previewing. The all-in-one preview, if supplied separately, is a snapshot; edit the actual website files for ongoing work.
